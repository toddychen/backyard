## Playground Service (`services/playground`)

### Redis Connection Monitor

Added `monitor/RedisConnectionMonitor` — a self-healing monitor for the Redis connection.

**Design decisions:**
- Since Redis is a cache layer (not authoritative), Redis failures degrade gracefully to origin lookups — no need to gate k8s readiness on Redis health
- Instead of resetting on the first failure (noisy), accumulates **consecutive** failures and only resets after 3 in a row (~90s of bad state), distinguishing transient blips from a genuinely stuck connection
- On reset, calls `LettuceConnectionFactory.resetConnection()` on the single shared Lettuce connection factory, forcing a fresh connection on the next cache access
- Counter resets to 0 on any successful ping; logs a recovery `INFO` if it was previously failing
- Guarded with `@Profile("!home")` since the home profile has no Redis
- `@EnableScheduling` added to `PlaygroundApplication`

**Files changed:**
- `PlaygroundApplication.java` — added `@EnableScheduling`
- `monitor/RedisConnectionMonitor.java` — new class

**To test in kind:** scale Redis deployment down to 0, watch playground logs for ping failure warnings, scale back up to confirm recovery log.

### API Localization

Implemented full locale-awareness across the request pipeline using the standard `Accept-Language` header pattern.

**Design decisions:**
- `ClientLocaleContext` record holds three signals per request: `raw` (original header), `locale` (resolved `SupportedLocale`), and `region` (ISO 3166-1 country code extracted from the raw header, e.g. `"CA"` from `"en-CA"`)
- `ClientLocaleContextHolder` uses `InheritableThreadLocal` so virtual threads spawned by `FanOut` automatically inherit the request's locale at creation time — no explicit propagation needed
- Region is extracted from the raw header by scanning ranges in priority order and matching by resolved language, not from `resolved.toLocale().getCountry()` (which is always empty because our `SupportedLocale` candidates use bare language tags like `"en"`, not `"en-US"`)
- `LocaleFilter` runs at `@Order(0)`, before `AccessLogFilter`, so `MDC("locale", ...)` is available in every log line for the request
- `LocaleInterceptor` is generic — takes a `Function<SupportedLocale, String>` mapper so it works for any upstream client with its own locale tag format
- Yahoo Sports only supports `en-US` and `es-US`; all other locales fall back to `en-US`. Modeled as `YahooSportsLocale` enum with `fromServiceLocale()` method
- `SupportedLocale.fromLanguageTag()` does exact match first, then language-prefix fallback (e.g. `"en-CA"` → `EN`)
- Cache key for `GameService.getGameDetails` includes locale: `"#gameId + ':' + T(...LocaleContextHolder).locale.toLanguageTag()"` — uses full BCP 47 tag so `zh-TW` and `zh-CN` cache separately
- Added `locale={}` to the Combined Log Format line in `AccessLogFilter` (reads from MDC set by `LocaleFilter`)
- Resilience4j instance names updated to use explicit client names: `ambee`, `yahoo_sports`, `google_pollen` — circuit breaker keys are `<clientName>-<methodName>`, retry keys are `<clientName>`

**`SupportedLocale` enum:** EN, FR, ES, ZH_TW (`"zh-TW"`), ZH_CN (`"zh-CN"`), JA, DE, PT_BR (`"pt-BR"`)

**Files created:**
- `context/ClientLocaleContext.java` — immutable record (raw, locale, region)
- `context/ClientLocaleContextHolder.java` — static `InheritableThreadLocal` wrapper
- `data/locale/SupportedLocale.java` — service-level locale enum with two-step `fromLanguageTag()`
- `data/locale/YahooSportsLocale.java` — Yahoo locale mapping (en-US / es-US only)
- `filter/LocaleFilter.java` — resolves `Accept-Language` → `ClientLocaleContext`, sets response headers
- `client/interceptor/LocaleInterceptor.java` — adds `Accept-Language` to Yahoo outbound requests

**Files modified:**
- `client/interceptor/LoggingInterceptor.java` — added `clientName` field, logs `[clientName] METHOD URL`
- `client/config/ClientConfig.java` — wired `LocaleInterceptor` into Yahoo client; `clientName` local variable per bean used for both logging and resilience naming
- `filter/AccessLogFilter.java` — appended `locale={}` to Combined Log Format line
- `service/GameService.java` — locale included in `@Cacheable` key
- `application.properties` — resilience4j instance names updated to `yahoo_sports-*` and `google_pollen-*`
- `controller/TestController.java` — added `GET /test/locale` endpoint returning raw, supportedLocale, region, yahooSportsLocale

**Response headers set by `LocaleFilter`:**
- `Vary: Accept-Language` — tells HTTP caches the response varies by locale
- `Content-Language: <tag>` — tells clients what language the response body is in
