# 2026-04-03

## Playground Service (`services/playground`)

### User Auth System

Implemented JWT-based authentication with refresh tokens backed by MySQL.

**Design decisions:**
- Access tokens are short-lived JWTs (signed with HMAC-SHA256); refresh tokens are opaque UUIDs
  stored in MySQL with expiry
- `AuthService` handles login, token refresh, and logout; `JwtTokenService` issues and validates
  JWTs; `SecretManagerLoader` loads the JWT signing key from GCP Secret Manager in stage/prod
- `JwtAuthenticationFilter` validates the `Authorization: Bearer` header on every request and
  populates `SecurityContextHolder`
- `SecurityConfig` uses Spring Security 6 filter chain — stateless (no session), CSRF disabled
- `HomeSecurityConfig` (`@Profile("home")`) permits all — no auth overhead for long-running local
  jar
- Refresh tokens are cleaned up by `RefreshTokenCleanupService` (scheduled)
- MySQL used for auth data (users, refresh tokens); H2 used for Dory reminders — two separate
  `DataSource` beans (`MysqlDataSourceConfig`, `H2DataSourceConfig`)

**New endpoints:**
- `POST /api/v1/auth/login` — returns access + refresh tokens
- `POST /api/v1/auth/refresh` — exchanges refresh token for new access token
- `POST /api/v1/auth/logout` — invalidates refresh token
- `GET /api/v1/users/me` — returns current user info

**Files created:**
- `dao/AuthDao.java` — raw JDBC for auth operations
- `data/auth/` — `User`, `RefreshToken`, `UserRepository`, `RefreshTokenRepository` JPA entities
- `data/persist/mysql/MysqlDataSourceConfig.java`, `data/persist/h2/H2DataSourceConfig.java`
- `security/SecurityConfig.java`, `security/HomeSecurityConfig.java`
- `security/JwtTokenService.java`, `security/JwtAuthenticationFilter.java`
- `security/SecretManagerLoader.java`
- `service/AuthService.java`, `service/RefreshTokenCleanupService.java`
- `controller/AuthController.java`, `controller/UserController.java`

### Data Class Refactor

Renamed data layer to enforce clear separation between API models and persistence entities.

**Convention:**
- `data/model/` — DTO suffix (e.g. `GameDTO`, `ReminderEntryDTO`) — internal API data model,
  never JPA entities
- `data/persist/h2/` — H2 JPA entities (Dory reminders)
- `data/persist/mysql/` — MySQL JPA entities (users, refresh tokens)

This prevents name collisions (e.g. old `Game` entity vs new `GameDTO`) and makes the layer
boundary explicit.

**Files renamed/moved:**
- `data/dory/ReminderEntity` → `data/persist/h2/dory/ReminderEntry`
- `data/dory/ReminderRepository` → `data/persist/h2/dory/ReminderRepository`
- `data/auth/*` → `data/persist/mysql/auth/*`
- `data/sport/game/Game` → `data/model/sport/GameDTO`
- `data/weather/pollen/PollenCategory` → `data/model/weather/pollen/PollenCategoryDTO`
- `data/locale/SupportedLocale` → `data/model/locale/SupportedLocaleDTO`
- `data/locale/YahooSportsLocale` → `data/model/locale/YahooSportsLocaleDTO`
