Reorganized the playground package structure to make transport boundaries explicit.

**Before → After:**
- `client/` → `client/rest/` (HTTP clients) and `client/grpc/` (gRPC clients)
- `controller/`, `filter/`, `security/` → `server/rest/controller/`, `server/rest/filter/`,
  `server/rest/security/`
- `server/grpc/` — new, for gRPC server-side code
- `security/JwtTokenService` → `jwt/JwtTokenService`
- `security/SecretManagerLoader` → `secret/SecretManagerLoader`
- `controller/config/OpenApiConfig` → `server/rest/apidocs/OpenApiConfig`
- `SecurityConfig` + `HomeSecurityConfig` merged into one file with nested static classes:
  `SecurityConfig.JwtSecured` (`@Profile("!home")`) and `SecurityConfig.PermitAll`
  (`@Profile("home")`)

## gRPC Server

### Package structure
Inbound transport lives under `server/grpc/`, outbound under `client/grpc/`, mirroring the existing
`server/rest/` and `client/rest/` layout.

### Proto files
Two proto files under `src/main/proto/com/backyard/playground/grpc/`:
- `echo/echo.proto` — `Echo` service with `EchoUnary` (unary) and `EchoServerStream` (server
  streaming) RPCs, used as a minimal demo
- `sport/sport.proto` — `Sport` service mirroring the REST sport endpoints (`GetTeamGames`,
  `GetGameDetails`)

Package convention: `com.backyard.playground.grpc.<service>` keeps gRPC namespaces isolated from
REST and common packages.

### Server lifecycle
`GrpcServerConfig` implements `SmartLifecycle` to manage the Netty gRPC server on port 9090.
Virtual thread executor (`Executors.newVirtualThreadPerTaskExecutor()`) is used so
`InheritableThreadLocal` (locale context) propagates correctly, matching REST behavior.

Registered services: `GrpcEchoService`, `GrpcSportService`, gRPC health service, proto reflection
(enables `grpcurl list`).

### Server interceptors (`server/grpc/interceptor/`)
Three interceptors registered in reverse order (last registered = outermost):

```
Registration order:  Exception → AccessLog → Locale
Effective order:     Locale → AccessLog → Exception → service
```

- **`GrpcLocaleInterceptor`** — reads `accept-language` metadata, resolves BCP 47 locale via
  shared `ClientLocaleResolver`, sets `ClientLocaleContextHolder` + MDC. Clears on
  `onComplete`/`onCancel`.
- **`GrpcAccessLogInterceptor`** — wraps `ServerCall.close()` via `SimpleForwardingServerCall`;
  logs method, status code, duration, locale after the call completes.
- **`GrpcExceptionInterceptor`** — wraps `onHalfClose()` via `SimpleForwardingServerCallListener`;
  catches exceptions and maps to gRPC status codes. Never leaks stack traces to clients.

Exception mapping (server-side):

| Domain exception | gRPC status |
|---|---|
| `BadRequestException` | `INVALID_ARGUMENT` |
| `UnauthorizedException` | `UNAUTHENTICATED` |
| `ForbiddenException` | `PERMISSION_DENIED` |
| `NotFoundException` | `NOT_FOUND` |
| `ConflictException` | `ALREADY_EXISTS` |
| `ServiceUnavailableException` | `UNAVAILABLE` |
| `CallNotPermittedException` | `UNAVAILABLE` |
| `Exception` (unhandled) | `INTERNAL` |

### Shared locale resolution
`ClientLocaleResolver` (in `context/`) extracted from `LocaleFilter` — shared static utility used
by both `LocaleFilter` (REST) and `GrpcLocaleInterceptor` (gRPC).

## gRPC Client

### Google Cloud Natural Language API
Added as an example of a real outbound gRPC client with API key auth.

**Dependency:** `grpc-google-cloud-language-v2:2.89.0` (explicit — not pulled transitively by
`google-cloud-language`; only proto message classes come transitively).

**API key:** `GOOGLE_LANGUAGE_API_KEY` env var (set in fish `config.fish` for local dev),
referenced in `application.properties` as `google.language.api-key=${GOOGLE_LANGUAGE_API_KEY:}`.
Stage/prod: load from GCP Secret Manager via `SecretManagerLoader`.

### Channel (`GrpcClientConfig`)
`googleLanguageChannel` bean — `NettyChannelBuilder` to `language.googleapis.com:443` with:
- TLS via `GrpcSslContexts.forClient().build()`
- `x-api-key` header attached to every call via `MetadataUtils.newAttachHeadersInterceptor`
- `GrpcClientLoggingInterceptor("google_language")` — logs method name, status, duration on close
- `@Bean(name = "googleLanguageChannel")` + `@Qualifier` for explicit matching when multiple
  channels exist

`withDeadlineAfter(30, TimeUnit.SECONDS)` set on the stub — grpc-java has no channel-level
deadline; `withDeadlineAfter` resets per call (vs `withDeadline` which is a fixed point in time).

### Client structure
- `GoogleLanguageClient` — interface with `analyzeSentiment()` and `analyzeEntities()`
- `GoogleLanguageClientImpl extends BaseClient` — wraps each stub call with `rpc()`
- `BaseClient` — base class for all gRPC client impls; `rpc(Supplier<T>)` catches
  `StatusRuntimeException` and maps to domain exceptions in one place; subclasses need no
  try/catch per method

Exception mapping (client-side):

| gRPC status | Domain exception |
|---|---|
| `NOT_FOUND` | `NotFoundException` |
| `INVALID_ARGUMENT` | `BadRequestException` |
| `UNAUTHENTICATED` | `UnauthorizedException` |
| `PERMISSION_DENIED` | `ForbiddenException` |
| `UNAVAILABLE` | `ServiceUnavailableException` |
| `DEADLINE_EXCEEDED` | `ServiceUnavailableException` |
| `RESOURCE_EXHAUSTED` | `ServiceUnavailableException` |
| default | `ServiceUnavailableException` |

### Client interceptors (`client/grpc/interceptor/`)
- **`GrpcClientLoggingInterceptor`** — logs once in `onClose` (method, status, duration); no
  startup log since `onClose` always fires including on error

### REST client timeout (added same day)
`JdkClientHttpRequestFactory` now has:
- `connectTimeout(Duration.ofSeconds(5))` on `HttpClient` — TCP+TLS handshake
- `setReadTimeout(Duration.ofSeconds(10))` on the factory — per-request response timeout

Previously no timeout was set; calls could hang indefinitely.
